- **003 and 005 before 010**: the dependency upgrade (Compose, Kotlin) is the riskiest change here;
  the new tests are its safety net.
- **007 ↔ 012**, **004 ↔ 011 ↔ 013**: they edit the same functions (`ProjectStore.create`;
  `RingtoneInstaller` / export). Land one, rebase the next; don't run them in parallel worktrees
  without expecting conflicts.

- **008 after the README-touching plans in flight** (001, 002) to avoid merge conflicts; later plans
  that change documented behaviour (011, 012, 013) update the README themselves.
- **011, 012, 013, 014** are product-direction plans the maintainer asked for; their STOP

## Findings considered and rejected

- **Timeline redraw cost on long songs**: `Timeline.drawLanes` only samples the visible width
  (every ≥2 px), so a 10-minute song costs the same per frame as a 10-second one.
- **Pad hit list growing without bound**: `PadPerformance.forgetEndedBefore` prunes ended hits
  every tick.
- **Glyph brightness range 0–4095 is a guess**: the SDK's own default lit value is 4000
  (`GlyphFrame.DEFAULT_LIGHT`), confirming the 12-bit range.
- **Gamma 1.6 makes low levels too dark**: a recorded decision (ADR 0006).
- **Export builds the ringtone in memory**: a recorded decision (ADR 0004); files are a few MB.
- **Light document confined to the main thread**: a recorded decision (ADR 0001).
- **Export renames the project even if cancelled** (`StudioSession.export` sets the name before
  encoding): minor and arguably intended (the name you typed is kept); not worth a plan.
- **`ConstantLocale` lint warning** (`HomeScreen.dateFormat` captures the locale at startup): a
  locale change mid-session shows old month names until restart; cosmetic.
